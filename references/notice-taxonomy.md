# 通知分类与字段抽取口径

本文件是 Step 3「AI 精判」的判定标准。规则层只做召回，**是否算通知、算哪一类、字段填什么，全部按本文件执行**。

## 一、什么算「通知」

### 判定为通知（满足任一条）

1. **群体告知**：面向一个群体发布的信息，含时间/地点/要求中的至少一项。
   例：「本周五下午3点在B301开班会，请全体成员务必参加」
2. **明确的行动要求**：要求对方做某件事，且有可辨识的时间点或截止。
   例：「周五之前把报价单发我邮箱」
3. **时间或安排的变更**：修改、取消、推迟、提前已定的事项。
   例：「原定3月12日的模拟考推迟到3月19日」
4. **需要回应的征集**：报名、接龙、统计、填写、确认。
   例：「接龙报名春游，截止到3月10日晚上8点」

### 判定为**不是**通知（必须丢弃）

| 类型 | 例子 | 原因 |
|------|------|------|
| 寒暄问候 | 「同学们早上好」 | 无信息量 |
| 纯应答 | 「收到」「好的」「嗯」 | 无信息量 |
| 日常闲聊 | 「晚上一起吃饭吗」「哈哈这个视频好笑」 | 无确定安排 |
| 情绪表达 | 「好累啊」「烦死了」 | 无行动项 |
| 已完成事项的复述 | 「我昨天交了」 | 非待办 |
| 纯媒体消息 | 图片、表情、语音（无转写） | 无可抽取文本 |
| 广告/营销转发 | 含明显推销链接 | 非个人通知 |

> 边界判断：**「有具体时间或明确要求」** 是分水岭。
> 「有空一起吃个饭」→ 不是通知；「周六晚上七点老地方吃饭」→ 是通知。

## 二、通知类型（`notice_type`）

固定从下列取值，不要自创：

| 类型 | 适用范围 | 示例 |
|------|----------|------|
| `会议` | 会议、例会、班会、答辩、讲座 | 周五班会 |
| `活动` | 聚餐、团建、出游、比赛、体检 | 春游 |
| `报名` | 报名、接龙、统计、征集 | 接龙报名 |
| `缴费` | 交费、班费、报销、付款 | 班费50元 |
| `提交材料` | 交文件、交作业、交复印件 | 交学生证复印件 |
| `变更` | 推迟、提前、取消、改地点/改时间 | 模拟考推迟 |
| `放假调课` | 放假、调休、补课、停课 | 五一调休 |
| `考试` | 考试安排、考场、准考证 | 四级模拟考 |
| `值班排班` | 值班、排班、加班 | 周末值班表 |
| `待办` | 单聊中的个人约定与承诺 | 周五前发报价单 |
| `提醒` | 纯提醒、无新增信息 | 记得带学生证 |
| `其他` | 确实构成通知但归不入上述 | — |

同一件事跨多类时，取**最主要的那一类**（如「报名春游」取 `报名` 而非 `活动`）。

## 三、字段抽取规则

| 字段 | 取值来源 | 缺省处理 |
|------|----------|----------|
| `notice_time` | **消息本身的时间戳**，取自候选的 `anchor_time`。这是表格的「通知时间」列 | 必填，不可空 |
| `notice_type` | 见上表 | 归不入则填 `其他` |
| `title` | 通知事项的凝练，**≤20 字**，动宾或名词短语 | 必填 |
| `event_time` | 通知指向的**发生时间**（开会时间、出发时间） | 找不到留 `""` |
| `deadline` | **截止时间**（报名截止、提交截止） | 找不到留 `""` |
| `location` | 地点（房间号、地址、店名） | 找不到留 `""` |
| `audience` | 面向对象（全体成员 / 某小组 / 我） | 找不到留 `""` |
| `action_required` | `需参加` / `需报名` / `需缴费` / `需提交` / `需回复` / `无需回应` | 按语义判断 |
| `confidence` | `high` / `medium` / `low` | 必填 |
| `evidence` | **原文摘录**，支持该判定的原话 | 必填 |

### 时间归一化

- 相对时间**尽量换算**成绝对日期，并在 `evidence` 里保留原话。
  例：通知时间 2026-03-02，"本周五" → `2026-03-06`；"下周六" → `2026-03-14`。
- 换算依据是 `notice_time`（通知发出那天），**不是**今天。
- 只有日期没有钟点时写 `2026-03-06`；有钟点写 `2026-03-06 15:00`。
- 无法确定绝对日期时，原样保留相对表述（如 `下周三`），并降 `confidence` 到 `medium`。
- **禁止**编造：原文没有的时间，一律留空。

### 置信度标准

| 值 | 判据 |
|----|------|
| `high` | 明确的通知措辞 + 至少一个具体时间/地点/要求 |
| `medium` | 是通知但字段不全，或需换算相对时间，或上下文有歧义 |
| `low` | 疑似通知，证据薄弱；**必须在交付时单独列出供人工核对** |

## 四、去重与合并

同一件事常被多次提及，处理原则：**保留最终态**。

典型序列：

```
09:28  周五下午3点在B301开班会
10:15  补充：班会改到下午4点
10:40  地点换成A203
```

→ 合并为**一条**：`title = "周五班会（时间改16:00，地点A203）"`，
`event_time = 2026-03-06 16:00`，`location = A203`，`confidence = high`。
被合并的候选不单独输出。

判据：**同一会话 + 同一事项 + 时间相近（同一天内）** 即视为同一件事。

---

## 五、示例（判定与抽取）

**输入候选**（群聊，`anchor_time = 2026-03-02 09:56:00`）：

```
另外接龙报名春游，下周六（3月14日）去青龙峡，费用120元，
报名截止到3月10日晚上8点，回复我一下我统计人数。
```

**输出**：

```json
{
  "notice_type": "报名",
  "title": "春游报名（青龙峡）",
  "event_time": "2026-03-14",
  "deadline": "2026-03-10 20:00",
  "location": "青龙峡",
  "audience": "全体成员",
  "action_required": "需报名",
  "confidence": "high",
  "evidence": "另外接龙报名春游，下周六（3月14日）去青龙峡，费用120元，报名截止到3月10日晚上8点，回复我一下我统计人数。"
}
```

注意：`notice_time` 是**消息发出时间** 09:56，而 `event_time` 是**活动时间** 03-14，
两者不可混淆 —— 这正是表格同时保留「通知时间」和「发生时间」两列的原因。
